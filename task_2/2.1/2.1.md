Decision Tree Classification

The task uses a decision tree to predict yeast protein localization classes. I first compare a default tree with a tuned tree using stratified cross-validation, then inspect its class-level predictions, and finally compare a small decision tree I wrote myself with scikit-learn’s implementation.

## 1. Imports and data setup

```python
import numpy as np, pandas as pd, matplotlib.pyplot as plt
from sklearn.tree import DecisionTreeClassifier
from sklearn.model_selection import StratifiedKFold, GridSearchCV, cross_validate, cross_val_predict
from sklearn.metrics import make_scorer, matthews_corrcoef, ConfusionMatrixDisplay, classification_report
```

- `DecisionTreeClassifier` is the library tree used for the baseline, tuned model, and comparison.
- The model-selection functions provide stratified folds, hyperparameter search, cross-validation scores, and predictions made on held-out folds.
- The metrics help evaluate overall and class-by-class performance.

```python
df = pd.read_csv('yeast.csv')
X, y = df.drop(columns='name').values, df['name'].values
print(df['name'].value_counts())
```

I load the data and separate it into:

- `X`: all predictor columns, with `name` removed.
- `y`: the `name` column, which contains the class label.

The class counts show that the dataset is imbalanced: some classes have many more observations than others. That is why I look beyond accuracy and include macro-averaged metrics and MCC. The relative path assumes I run the notebook from the folder containing `yeast.csv`.

## 2. Baseline tree with stratified cross-validation

```python
cv = StratifiedKFold(5, shuffle=True, random_state=0)
```

I split the data into five folds. Stratification keeps each fold’s class proportions close to those of the full dataset, which matters when some classes are small. Shuffling mixes the rows before splitting, and `random_state=0` makes the folds repeatable.

```python
scoring = {
    'accuracy': 'accuracy',
    'f1': 'f1_macro',
    'recall': 'recall_macro',
    'mcc': make_scorer(matthews_corrcoef),
    'auc': 'roc_auc_ovr'
}
```

I define several metrics because a single score can hide important behavior:

- **Accuracy:** fraction of predictions that are correct overall.
- **Macro F1:** calculate F1 separately for each class and average them equally, so large classes do not dominate the score.
- **Macro recall:** average each class’s recall equally.
- **MCC:** a balanced summary based on the confusion matrix; it works for multiclass classification too.
- **One-vs-rest ROC AUC:** evaluates how well the model ranks each class against all the others, then aggregates across classes.

```python
def evaluate(model):
    r = cross_validate(model, X, y, cv=cv, scoring=scoring)
    return pd.Series({k: r['test_'+k].mean() for k in scoring}).round(3)
```

This helper evaluates a model on each of the five held-out folds. It returns the mean test score for each metric, rounded to three decimals. Averaging across folds gives a more reliable estimate than scoring on one train/test split.

```python
base = evaluate(DecisionTreeClassifier(random_state=0))
```

This is the baseline: a decision tree with its default settings. I keep the random state fixed so that any randomness inside the tree is reproducible.

## 3. Tune the tree with an inner grid search

```python
grid = {
    'max_depth': [3, 5, 8, None],
    'min_samples_leaf': [1, 5, 10],
    'criterion': ['gini', 'entropy']
}
```

I choose a small set of tree settings to compare:

- `max_depth` limits how many splits a path can have. Shallower trees are simpler and less likely to overfit.
- `min_samples_leaf` requires each final leaf to contain a minimum number of observations. This also discourages overly specific rules.
- `criterion` selects the impurity measure used to choose splits: Gini impurity or entropy.

```python
tuned_model = GridSearchCV(
    DecisionTreeClassifier(random_state=0),
    grid,
    scoring='f1_macro',
    cv=4
)
tuned = evaluate(tuned_model)
```

`GridSearchCV` tests every combination of settings using four inner folds and chooses the one with the best macro F1. Macro F1 is the search objective because the classes are imbalanced and I want each class to count equally.

Then `evaluate` puts that search inside the five-fold outer evaluation. For each outer fold, the grid search chooses settings using only that fold’s training portion, and the selected tree is scored on the untouched outer test fold. This is **nested cross-validation** and gives a less biased estimate of tuned-model performance than reporting the same folds used to choose the settings.

```python
pd.DataFrame({'baseline': base, 'tuned': tuned})
```

This table makes it easy to compare baseline and tuned mean scores side by side. In the saved output, tuning improved most metrics, though macro F1 improved only modestly.

## 4. Per-class report and confusion matrix

```python
pred = cross_val_predict(tuned_model, X, y, cv=cv)
```

This produces an out-of-fold prediction for every observation. Each prediction comes from a model that did not train on that observation. Because the estimator is a `GridSearchCV`, it performs its inner hyperparameter search within each training fold before predicting the corresponding held-out fold.

```python
print(classification_report(y, pred, zero_division=0))
```

The report gives precision, recall, F1, and support for every class. `zero_division=0` prevents undefined metrics for a class with no predicted examples from causing a warning; the score is shown as zero in that case.

```python
ConfusionMatrixDisplay.from_predictions(y, pred, cmap='Blues', colorbar=False)
plt.show()
```

The confusion matrix shows which true classes the model predicts correctly and which it mixes up. It complements the summary metrics, especially because performance can differ considerably by class.

## 5. Gini impurity for my own tree

```python
def gini(y):
    p = np.unique(y, return_counts=True)[1] / len(y)
    return 1 - (p**2).sum()
```

This calculates Gini impurity from class proportions. It is low when most observations belong to one class and high when the classes are mixed. The tree uses this to decide whether a split makes the child groups purer.

## 6. My decision tree implementation

```python
class MyTree:
    def __init__(self, max_depth=5, min_leaf=5):
        self.max_depth, self.min_leaf = max_depth, min_leaf
```

`MyTree` stores two regularization settings: the maximum depth and the minimum number of observations allowed on either side of a split.

### Fit one node and search for a split

```python
def fit(self, X, y, depth=0):
    self.label = pd.Series(y).mode()[0]
    best, self.left = (0, None, None), None
```

At every node, I save the majority class as the prediction if the node becomes a leaf. I also initialize the best split as “no split yet.”

```python
if depth < self.max_depth and gini(y) > 0:
```

I only look for a split if the depth limit has not been reached and the node is not already pure.

```python
for f in range(X.shape[1]):
    vals = np.unique(X[:, f])
    for t in (vals[1:] + vals[:-1]) / 2:
```

For each feature, I sort its unique observed values and test the midpoint between each adjacent pair as a candidate threshold. Midpoints are useful because they divide the observed values without placing a threshold exactly on one of them.

```python
m = X[:, f] <= t
if m.sum() < self.min_leaf or (~m).sum() < self.min_leaf: continue
```

The Boolean mask `m` divides observations into left (`<= t`) and right (`> t`) groups. I reject splits that would leave either side with fewer than `min_leaf` observations.

```python
gain = gini(y) - (m.mean()*gini(y[m]) + (~m).mean()*gini(y[~m]))
if gain > best[0]: best = (gain, f, t)
```

This computes the parent Gini minus the weighted average Gini of the children. The weights are the proportions of observations sent to each side. A larger positive gain means the split reduces impurity more, so I keep the feature and threshold with the largest gain.

### Grow the left and right subtrees

```python
_, self.f, self.t = best
if self.f is not None:
    m = X[:, self.f] <= self.t
    self.left = MyTree(...).fit(X[m], y[m], depth+1)
    self.right = MyTree(...).fit(X[~m], y[~m], depth+1)
return self
```

If I found a valid split, I recursively create a left and right `MyTree`, each trained only on the observations routed to that side. The `depth+1` moves the recursion one level down. If no split was selected, `self.left` stays `None`, so the node is a leaf.

### Predict with the tree

```python
def _one(self, x):
    if self.left is None: return self.label
    return (self.left if x[self.f] <= self.t else self.right)._one(x)
```

For one observation, I follow the thresholds from the root until I reach a leaf, then return that leaf’s stored majority class.

```python
def predict(self, X):
    return np.array([self._one(x) for x in X])
```

I apply `_one` to each row and return all predicted labels as a NumPy array.

```python
def get_params(self, deep=True): ...
def set_params(self, **p): ...
```

These methods make the class look more like a scikit-learn estimator by exposing and updating its parameters. They are useful if I later want to plug this tree into scikit-learn tools. In the current notebook, I do not use `MyTree` with `GridSearchCV`.

## 7. Compare my tree with scikit-learn’s tree

```python
sk = DecisionTreeClassifier(max_depth=5, min_samples_leaf=5, random_state=0)
rows = {'scratch': [], 'sklearn': []}
```

I set the library tree to the same depth and minimum leaf size as my tree, then create lists to collect fold scores for each implementation.

```python
for tr, te in cv.split(X, y):
    for name, m in [('scratch', MyTree(5, 5)), ('sklearn', sk)]:
        p = m.fit(X[tr], y[tr]).predict(X[te])
```

For each stratified fold, I fit each implementation on the training indices and predict the held-out indices. This is a fairer comparison than scoring on the training data.

```python
rows[name].append([
    accuracy_score(y[te], p),
    f1_score(y[te], p, average='macro'),
    matthews_corrcoef(y[te], p)
])
```

I record accuracy, macro F1, and MCC for each fold. These provide both an overall measure and metrics less dominated by the largest classes.

```python
pd.DataFrame({k: np.mean(v, 0) for k, v in rows.items()}, ...).round(3)
```

Finally, I average each metric across folds and compare the scratch implementation with scikit-learn. Similar results suggest that my implementation is behaving similarly for these settings. They do not prove the implementations are identical: details such as tie-breaking, split candidate handling, or empty branches can differ.

## Overall workflow

1. Load the yeast data and separate the predictors from the class label.
2. Inspect class frequencies to understand the imbalance.
3. Establish a baseline decision tree using stratified five-fold CV.
4. Tune tree depth, minimum leaf size, and split criterion with an inner grid search, then evaluate with an outer CV loop.
5. Inspect out-of-fold class predictions using a classification report and confusion matrix.
6. Implement a simple Gini-based tree from scratch.
7. Compare the scratch tree and library tree on the same folds.

- The dataset is imbalanced, so macro F1, macro recall, MCC, and per-class results are useful alongside accuracy.
- The rarest class has only five rows, so its scores will be unstable and each fold has very little information about it.
- The dataset contains some repeated feature rows. In ordinary stratified CV, identical rows can end up in different folds, which may make evaluation a little optimistic. A stricter evaluation could keep identical feature rows in the same fold.
- This notebook does not save a fitted final model. It evaluates models; if I need one for later predictions, I would select the final settings and fit that model on all available training data separately.
