Linear Regression: Predicting the Close Price

The task: use train.csv to train a model, use the model to predict the Close price in test.csv, and report the accuracy. 

Step 1

```python
import numpy as np
import pandas as pd
from sklearn.linear_model import LinearRegression
from sklearn.metrics import r2_score, mean_absolute_error, mean_squared_error

train = pd.read_csv("train.csv")
test = pd.read_csv("test.csv")
print("Train shape:", train.shape)
print("Test shape:", test.shape)
```

Explanation: The import lines bring in the tools I need: numpy for maths, pandas for tables, LinearRegression for the model, and three scoring functions to check the model later. read_csv loads each file into a table. The print lines show the size of each table.

Load train.csv and test.csv into two separate tables. Train has 283,085 rows and test has 177,063 rows. Keeping them separate makes sure the test data is never used for training.


Step 2

```python
number_columns = [
    "high", "low", "momentum_index", "beta_indicator", "risk_premium",
    "volatility_factor", "technical_score", "oscillator_value",
    "liquidity_ratio", "open", "quant_index", "trend_strength",
    "market_sentiment", "volume", "alpha_signal",
]
```

Explanation: This is a list of the number columns I will give to the model as inputs. The column close is not in the list because it is the answer I want to predict. I also left out date and index.

Problem: The model needs to know which columns to learn from. Some columns, like index, are just row numbers and do not help predict a price.

Solution: Choose the 15 useful number columns as the inputs. Close is the output.


Step 3

```python
for col in number_columns:
    train[col] = train[col].replace(0, np.nan)
    test[col] = test[col].replace(0, np.nan)

medians = train[number_columns].median()

train[number_columns] = train[number_columns].fillna(medians)
test[number_columns] = test[number_columns].fillna(medians)

train = train[train["close"].notna() & (train["close"] != 0)]
test = test[test["close"].notna() & (test["close"] != 0)]
print("Train rows after cleaning:", train.shape[0])
print("Test rows after cleaning:", test.shape[0])
```

Explanation: The first loop changes every 0 in the input columns into an empty cell. Then I find the median of each column from the train file only. fillna puts that median into every empty cell, in both files. The last two lines remove the rows where close is empty or 0.

Problem: The data has two kinds of missing values. Some cells are empty, and some are filled with a fake 0 that really means "no data" (almost every column has these). A model cannot handle empty cells, and the fake zeros would give it wrong information. Also, a stock does not really close at 0, so a row with no real close price cannot be learned from or used to check the model.

Solution: Turn the fake zeros into empty cells, then fill all the empty cells with the median. I took the medians from the train file only, so no information from the test file goes into training. Then remove the rows with no real close price. After cleaning, train has 280,078 rows and test has 176,495 rows.


Step 4

```python
symbol_columns = []
for value in train["symbols"].unique():
    name = "symbol_" + value
    train[name] = (train["symbols"] == value).astype(int)
    test[name] = (test["symbols"] == value).astype(int)
    symbol_columns.append(name)

feature_columns = number_columns + symbol_columns
```

Explanation: unique gives the four different stock names in the symbols column (MRO, HRS, ULTA, Low). For each name the loop makes a new column, for example symbol_MRO. The part (train["symbols"] == value) is True when the row has that stock, and astype(int) changes True to 1 and False to 0. The same thing is done to the test table so both have the same columns. The last line joins the number columns and the new symbol columns into one list of inputs.

Problem: The symbols column has words, and a model only understands numbers. The stocks also behave differently. MRO prices are much higher on average than the others, so the model needs to know which stock a row belongs to.

Solution: Make one 0/1 column for each stock (one-hot encoding). I did not number them 0, 1, 2, 3, because that would make the model think the stocks have an order.


Step 5

```python
X_train = train[feature_columns]
y_train = train["close"]

X_test = test[feature_columns]
y_test = test["close"]
```

Explanation: X means the inputs and y means the answer. X_train holds the input columns of the train table and y_train holds its close prices. X_test and y_test do the same for the test table.

Problem: The model has to be given the inputs and the answers separately.

Solution: Split each table into X (inputs) and y (close price). The model will learn from X_train and y_train. X_test will be used to make predictions, and y_test will be used only to check them.


Step 6

```python
model = LinearRegression()
model.fit(X_train, y_train)
```

Explanation: The first line creates an empty linear regression model. fit trains it. During training the model finds a weight for each input column, and then predicts close as a weighted sum of the inputs plus a starting number, in the form y = w1*x1 + w2*x2 + ... + b. It chooses the weights that make its guesses as close as possible to the real close prices in the train data.

Problem: I need a model that has learned how the input columns relate to the close price.

Solution: Train a linear regression model using only the train data. The test data is not used here.


Step 7

```python
predictions = model.predict(X_test)
```

Explanation: predict takes the input columns of the test table and uses the learned weights to calculate a close price for every row.

Problem: I need the model's predicted prices for the test file so I can compare them with the real ones.

Solution: Run the trained model on X_test. The result, predictions, holds one predicted close price per test row.


Step 8

```python
r2 = r2_score(y_test, predictions)
mae = mean_absolute_error(y_test, predictions)
rmse = np.sqrt(mean_squared_error(y_test, predictions))

print("Accuracy (R2 score):", round(r2 * 100, 2), "%")
print("Average error (MAE):", round(mae, 2))
print("RMSE:", round(rmse, 2))
```

Explanation: These lines compare the predicted prices with the real prices in y_test. r2_score gives the R2 score, mean_absolute_error gives the average size of the mistakes, and for RMSE I take the square root of the mean squared error, which punishes big mistakes more. round just shortens the numbers for printing.

Problem: Predictions are only useful if I know how close they are to the real prices. For a regression problem, plain "percent correct" does not work, because a predicted price is almost never exactly equal to the real one.

Solution: Use the R2 score as the accuracy. It shows how much of the up and down movement in the Close price the model explains, and 100% would be perfect. The results were:

Accuracy (R2 score): 96.92 %
Average error (MAE): 10.14
RMSE: 13.23

So the model explains about 97% of the variation in the Close price, and its predictions are off by about 10 on average. When I tested on a held-out part of the train file, I got about 99%, so the test file scores a bit lower. The test file has some columns that are more spread out than in the train file, which probably explains part of the difference.
