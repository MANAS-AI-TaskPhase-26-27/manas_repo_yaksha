Logistic Regression

In this task, I wanted to build a model that predicts whether a crime case is closed, using the columns available in the dataset. 

The goal is to use `crime_train.csv` to predict whether a crime case is closed (`Yes`) or not closed (`No`). 

This is a classification task: each case belongs to one of two classes. The notebook reports accuracy, which is the percentage of cases whose predicted class matches the real class.

The model starts by calculating a weighted sum of the input features. The weights describe how much each feature influences the result. Logistic regression passes this sum through the sigmoid function, which turns any real number into a value between 0 and 1. That value is interpreted as the probability that the case is closed.

For example, a probability of 0.8 means the model estimates an 80% chance that a case is closed. 0.5 is decision threshold: probabilities at least 0.5 become `Yes` (1), and probabilities below 0.5 become `No` (0).

Training means adjusting the weights to reduce binary cross-entropy, a cost that penalizes probabilities that are far from the correct answer. Gradient descent repeatedly measures how the cost would change and moves the weights a little in the direction that lowers it. One full pass through the training rows is an **epoch**. The notebook uses 300 epochs and records train and test results after each one.

Categorical words need a representation that a numerical model can use. One-hot encoding answers a simple question for every row—“is this the category?”—with a 1 or 0. I used the category values found in the training data to define the feature columns, then built those same columns for test. This is important because each weight must refer to the same feature in both datasets. It also avoids giving categories made-up numeric ranks.

**Solution:** Represent categories with 0/1 indicator columns and keep a list of the resulting input columns separate from the target.


```python
mean = train[number_columns].mean()
std = train[number_columns].std()
train[number_columns] = (train[number_columns] - mean) / std
test[number_columns] = (test[number_columns] - mean) / std

X_train = train[feature_columns].to_numpy(dtype=float)
y_train = train["closed"].to_numpy(dtype=float)
X_test = test[feature_columns].to_numpy(dtype=float)
y_test = test["closed"].to_numpy(dtype=float)

X_test = np.c_[np.ones(len(X_test)), X_test]
```

- `mean` and `std` contain one mean and one standard deviation for each numeric feature. The mean is the average; standard deviation describes how spread out the values are.
- `(value - mean) / std` standardizes the numeric features. Each value is expressed relative to its column's average and spread. The one-hot columns are left at 0 and 1 because only `number_columns` are transformed.
- Both statistics come from `train`. Applying the same train mean and standard deviation to test gives both sets the same scale without letting the test distribution influence preprocessing.
- `X` is the conventional name for the input feature matrix; `y` is the target vector. `.to_numpy(dtype=float)` converts the selected pandas columns into NumPy arrays containing floating-point numbers.
- `np.ones(len(X_train))` makes one 1 for each row. `np.c_[...]` puts that column of ones before the features. Its weight acts as the model's bias (intercept), so the model can shift its baseline probability without depending on a feature.

The target `closed` is already 0 or 1, so it is not standardized. The notebook reports `X_train` shape `(22489, 68)` and `X_test` shape `(9639, 68)`: each row has 67 encoded features plus one bias input.

This step helped me connect the prepared table to the mathematics of the model. I separated X, the information the model sees, from y, the answer it should learn. I standardized only the numeric inputs because values like year and hour have very different ranges. I calculated the scaling values from train and reused them on test so that the test set could not influence the preparation. I left the target as 0/1, and added a column of ones so the model could learn a baseline offset (the bias) along with its feature weights.

**Problem:** The numeric columns use different units and ranges, and matrix-based training needs numeric arrays. The model also needs a bias term.

**Solution:** Standardize numeric inputs using training statistics, convert inputs and targets to NumPy arrays, and add a constant-one column for the bias.


```python
def sigmoid(z):
    z = np.clip(z, -500, 500)
    return 1 / (1 + np.exp(-z))

def predict_proba(X, w):
    return sigmoid(X @ w)

def predict(X, w):
    return (predict_proba(X, w) >= 0.5).astype(int)

def cost(X, y, w):
    p = predict_proba(X, w)
    p = np.clip(p, 1e-15, 1 - 1e-15)
    return -(y * np.log(p) + (1 - y) * np.log(1 - p)).mean()

def accuracy(X, y, w):
    return (predict(X, w) == y).mean() * 100
```

### `sigmoid(z)`

The sigmoid formula, `1 / (1 + exp(-z))`, maps a score to a probability between 0 and 1. `np.clip(z, -500, 500)` keeps very large inputs within a range that avoids numerical overflow when `exp` is calculated.

### `predict_proba(X, w)`

`X @ w` is matrix multiplication. For each row, it combines the input values with their corresponding weights into one score. Passing the scores through sigmoid returns the estimated probability of a closed case.

### `predict(X, w)`

The `>= 0.5` comparison applies the decision threshold. `.astype(int)` turns the resulting true/false values into 1/0 predictions.

### `cost(X, y, w)`

This computes binary cross-entropy, the training objective for logistic regression. If the real label is 1, the `y * log(p)` term penalizes a low probability. If the real label is 0, the `(1-y) * log(1-p)` term penalizes a high probability. The leading minus sign makes the cost nonnegative in the usual probability range, and `.mean()` averages across rows. Lower cost is better.

`np.clip(p, 1e-15, 1 - 1e-15)` prevents taking `log(0)`, which is undefined and would make the result infinite.

### `accuracy(X, y, w)`

This compares each 0/1 prediction with the correct label. The mean of the matches is the fraction correct; multiplying by 100 makes it a percentage.

**Problem:** Training requires a probability model, a numeric objective to minimize, and a clear way to convert probabilities into class labels and measure correct predictions.

**Solution:** Implement sigmoid logistic regression, binary cross-entropy, a 0.5 classification threshold, and accuracy as reusable functions.


```python
learning_rate = 0.1
epochs = 300

w = np.zeros(X_train.shape[1])
m = len(y_train)

train_costs = []
test_costs = []
train_accs = []
test_accs = []

for epoch in range(1, epochs + 1):
    errors = predict_proba(X_train, w) - y_train
    gradient = (X_train.T @ errors) / m
    w = w - learning_rate * gradient

    train_costs.append(cost(X_train, y_train, w))
    test_costs.append(cost(X_test, y_test, w))
    train_accs.append(accuracy(X_train, y_train, w))
    test_accs.append(accuracy(X_test, y_test, w))
```

- `learning_rate = 0.1` sets how large each weight adjustment is. A step that is too large can overshoot a good solution; a step that is too small can make learning slow.
- `epochs = 300` sets the number of full training passes.
- `w = np.zeros(...)` starts every model weight at zero. There is one weight for every feature and for the bias column.
- `m` is the number of training examples. The four empty lists hold the values later used in the plots and final report.

For each epoch:

1. `predict_proba(X_train, w)` computes the current probability for each training case.
2. Subtracting `y_train` gives the probability error for each row. For logistic regression with cross-entropy, this difference is the key term in the gradient.
3. `X_train.T @ errors` combines those errors with each feature across all rows. Dividing by `m` averages the gradient across the training set.
4. `w = w - learning_rate * gradient` moves each weight opposite the gradient, in the direction expected to reduce the cost.
5. The code records cost and accuracy on both datasets. The weight update uses **only** `X_train` and `y_train`; test metrics are observations and do not affect the weights.

The printed lines show training progress. Across 300 epochs, the training cost changes only slightly, from about 0.6931 to 0.6926. Accuracy also stays near 50%.


Initialized all weights equally at zero, computed how wrong the probabilities were on training rows, and used the gradient to decide how to change each weight. I chose a learning rate of 0.1 and ran 300 epochs, recording progress as I went. I also calculated test metrics each epoch so I could observe generalization, but I kept those values out of the weight update. Watching the cost and accuracy barely move was an important finding: completing the training loop does not mean the features contain a strong pattern.

**Problem:** The initial weights do not yet make useful predictions. They need to be adjusted based on how the probabilities differ from the known training labels.

**Solution:** Use the analytic logistic-regression gradient and repeatedly update weights on training data. Record test scores only to monitor generalization, without using test labels to train.
