Linear Regression

The task: use train.csv to train a model, use the model to predict the Close price of the stocks in test.csv, and report the accuracy.

Linear regression predicts a number (here, the Close price) as a weighted sum of the input columns:

prediction = w0 * 1 + w1 * x1 + w2 * x2 + ... + w19 * x19

Each x is an input column (like high, low, volume). Each w is a weight, which tells the model how much that column matters. w0 is the bias, a starting number that does not depend on any column. Training means finding the weights that make the predictions as close as possible to the real Close prices.

Because this is regression, accuracy is measured with the R2 score and not with "percent correct", since a predicted price is almost never exactly equal to the real price.

Step 4

```python
for col in number_columns:
    train[col] = train[col].replace(0, np.nan)
    test[col] = test[col].replace(0, np.nan)

medians = train[number_columns].median()

train[number_columns] = train[number_columns].fillna(medians)
test[number_columns] = test[number_columns].fillna(medians)
```

`for col in number_columns:`: a for loop repeats the indented lines below it once for each item in the list. In each round, col holds one column name ("high", then "low", and so on).

`train[col]`: square brackets with a column name pick that one column out of the table.

`.replace(0, np.nan)`: finds every 0 in the column and swaps it with NaN. NaN means "Not a Number", and it is how pandas marks an empty cell. np.nan is NumPy's version of NaN.

`train[col] = ...`: saves the changed column back into the table. Without the "=", the change would be calculated and then thrown away.

The next line does the same for test. I apply the same cleaning rule to both files, so they stay consistent.

Why I turn 0 into empty: the data has fake zeros. Many cells have a 0 where the real value is missing (a stock does not really have a volume or a price of exactly 0). If I leave them, the model learns from wrong numbers. Turning them into empty cells puts them in the same group as the other missing values, so I can fix both kinds in one go.

`medians = train[number_columns].median()`: putting the list inside the square brackets picks all 15 columns at once. median() finds the middle value of each column (half of the values are smaller and half are bigger), and it ignores the empty cells. The result is one median per column, saved together with the column names.

Why only from train: the test file must be treated like data the model has never seen. If I used the test data to calculate anything, information from the test file would leak into training and the accuracy would look better than it really is. This mistake is called data leakage.

Why median and not mean: the median is not pulled by a few very big or very small values, but the mean is.

`.fillna(medians)`: fillna puts a value into every empty cell. Because medians has the column names attached, pandas matches them up, so each column gets its own median. The empty cells in the test file are filled with the train medians, again so that nothing comes from the test data.

Problem: The data has two kinds of missing values. Some cells are empty, and some contain a fake 0. A model cannot do maths with empty cells (the calculations would turn into NaN), and the fake zeros would give it wrong information. Deleting every row with a missing value would throw away a huge part of the data.

Solution: Turn the fake zeros into empty cells, then fill all the empty cells with the median of that column, using the medians calculated from the train file only.

Step 8

```python
mean = X_train.mean(axis=0)
std = X_train.std(axis=0)
X_train = (X_train - mean) / std
X_test = (X_test - mean) / std

X_train = np.c_[np.ones(len(X_train)), X_train]
X_test = np.c_[np.ones(len(X_test)), X_test]

# don't scale y (close)
```

`X_train.mean(axis=0)`: finds the average. axis=0 means "go down the rows", so I get one average for each column (19 numbers).

`X_train.std(axis=0)`: std is the standard deviation, which shows how spread out the values of a column are. Again, one number for each column.

`(X_train - mean) / std`: this is standardization. NumPy automatically subtracts each column's own mean from that column and divides by that column's own std (this automatic matching is called broadcasting). After this, every column has a mean of 0 and a standard deviation of 1.

`X_test = (X_test - mean) / std`: the test data is scaled with the mean and std of the train data, not its own. The test data should be treated as unseen, and the same ruler must be used for both.

Why scale: the columns are on very different scales (volume has huge numbers, while a score may be small). Gradient descent uses one learning rate for all weights, so with unscaled columns the big ones would dominate, and training would be very slow or blow up. With scaled columns every weight learns at a similar speed.

`np.ones(len(X_train))`: len gives the number of rows, and np.ones makes an array with that many 1s.

`np.c_[a, b]`: glues arrays together as columns, side by side. Here it puts the column of 1s in front of X, so X gets one extra column (20 columns now).

Why the column of 1s: the model is prediction = w0 * 1 + w1 * x1 + .... The column of 1s is multiplied by w0, which makes w0 the bias. So the bias is learned like every other weight inside a single matrix multiplication, and I do not need any special code for it. I add the column after the scaling, because a column of 1s has a std of 0, and dividing by 0 would break the scaling.

I scale the input columns (X), but I do not scale y, the Close price. Close is the value I am trying to predict, so it must stay in real prices. That way the predictions, the cost and the errors (MAE and RMSE) are all in real price units and mean something directly, and I never have to convert them back. Scaling the inputs is enough to make gradient descent behave well, because the step sizes depend on the input columns.

Problem: The input columns are on very different scales, which makes gradient descent unstable or slow, and the model has no way to learn the bias.

Solution: Standardize the input columns with the train mean and std (but leave the answer, close, as it is), and add a column of 1s for the bias. X_train now has 280,078 rows and 20 columns (1 bias + 19 inputs).


Step 9

```python
def predict(X, w):
    return X @ w


def cost(X, y, w):
    m = len(y)
    errors = predict(X, w) - y
    return (errors ** 2).sum() / m


def r2_score(y_real, y_pred):
    ss_res = ((y_real - y_pred) ** 2).sum()
    ss_tot = ((y_real - y_real.mean()) ** 2).sum()
    return 1 - ss_res / ss_tot
```

`def predict(X, w):`: def creates a function, a named piece of code that I can reuse. X and w are the inputs of the function. `return` sends the result back.

`X @ w`: the @ symbol is matrix multiplication. Each row of X (20 numbers) is multiplied with the 20 weights in w and the products are added up. That is exactly w0 * 1 + w1 * x1 + ... for every row, so one short line makes a prediction for all the rows at once. The result is one prediction per row.

`def cost(X, y, w):` the cost function measures how wrong the model is.

`m = len(y)`: the number of rows.

`errors = predict(X, w) - y`: the prediction minus the real answer, for every row.

`(errors ** 2)`: squares each error. Squaring makes every error positive, so the plus and minus mistakes cannot cancel each other, and it punishes big mistakes more than small ones.

`.sum()`: adds up all the squared errors.

`/ m`: divides by the number of rows to get the average. So the cost is the mean squared error (MSE). The cost is lower when the model is better, and 0 would be a perfect model. Because close is not scaled, the cost is measured in real price units (squared).

`def r2_score(y_real, y_pred):` this function gives the accuracy.

`ss_res = ((y_real - y_pred) ** 2).sum()`: the total squared error of my model (called the residual sum of squares).

`ss_tot = ((y_real - y_real.mean()) ** 2).sum()`: the total squared error if I just guessed the average price every time (the total sum of squares).

`return 1 - ss_res / ss_tot`: R2 compares my model with the lazy guess. R2 = 1 means perfect predictions. R2 = 0 means no better than always guessing the average. A negative value means worse than that. I multiply it by 100 later to show it as a percentage.

Problem: I need ways to make a prediction, to measure how wrong it is, and to turn that into an accuracy number, without using a library.

Solution: Write the three functions by hand: predict (the model), cost (what gradient descent reduces) and r2_score (the accuracy).


Step 10

```python
learning_rate = 0.1
epochs = 300

w = np.zeros(X_train.shape[1])
m = len(y_train)

train_costs = []
test_costs = []
train_accs = []
test_accs = []

for epoch in range(1, epochs + 1):
    # one step of gradient descent
    errors = predict(X_train, w) - y_train
    gradient = 2 * (X_train.T @ errors) / m
    w = w - learning_rate * gradient

    # save the cost
    train_costs.append(cost(X_train, y_train, w))
    test_costs.append(cost(X_test, y_test, w))

    # save the accuracy (predictions are already in real prices)
    train_pred = predict(X_train, w)
    test_pred = predict(X_test, w)
    train_accs.append(r2_score(y_train, train_pred) * 100)
    test_accs.append(r2_score(y_test, test_pred) * 100)

    print(f"Epoch {epoch:3d} | cost: {train_costs[-1]:.5f} | "
          f"train accuracy: {train_accs[-1]:.2f}% | "
          f"test accuracy: {test_accs[-1]:.2f}%")
```

`learning_rate = 0.1`: the size of each step downhill. If it is too big, the steps jump over the bottom and the cost blows up. If it is too small, learning is very slow. 0.1 works well with scaled input columns.

`epochs = 300`: how many times I go through the whole training data.

`w = np.zeros(X_train.shape[1])`: the starting weights. X_train.shape[1] is the number of columns (20), so w is 20 zeros, one weight for each column, including the bias. Starting at zero is fine here because the cost of linear regression is bowl-shaped, so there is only one bottom to reach, and it does not matter where I start.

`m = len(y_train)`: the number of training rows, used to average the gradient.

`train_costs = []` and the other three empty lists: places to store the cost and the accuracy after every epoch, for the printing and for the plots later.

`for epoch in range(1, epochs + 1):` range(1, 301) gives the numbers 1 to 300. The end number of range is not included, which is why I write epochs + 1. Each round of the loop is one epoch.

`errors = predict(X_train, w) - y_train`: step 1 and 2 of gradient descent. Predict with the current weights and subtract the real Close prices, which gives the error for every row.

`gradient = 2 * (X_train.T @ errors) / m`: step 3, the gradient. The gradient tells me how the cost changes when each weight changes. .T is the transpose, which flips the table so that rows become columns. X_train.T has 20 rows and 280,078 columns, so multiplying it with the errors (@) gives 20 numbers. For each weight, the calculation adds up (error * the value of that weight's column) over all the rows, and then dividing by m gives the average. The 2 comes from the derivative of the square. This is the derivative of the cost: the cost is (1 / m) * sum((X w - y)^2), and its derivative with respect to w is (2 / m) * X.T @ (X w - y). If a weight's gradient is positive, increasing the weight would increase the cost, so the weight should go down. If it is negative, the weight should go up.

`w = w - learning_rate * gradient`: step 4, the update. I move every weight a small step in the opposite direction of its gradient, which is downhill. The step size is the learning rate times the gradient. Because every update uses all the training rows, this is called batch gradient descent.

`train_costs.append(cost(X_train, y_train, w))`: after the update, calculate the new cost on the train data and add it to the end of the list. The cost is in real price units (squared and halved).

`test_costs.append(cost(X_test, y_test, w))`: calculate the cost on the test data with the same weights, only to watch the progress. The test data is never used in the gradient or the update, so the model still learns only from the train file.

`train_pred = predict(X_train, w)`: predict the train prices with the current weights. Close was never scaled, so these are already real prices and nothing needs to be converted back. The same is done for the test data with `test_pred`.

`r2_score(y_train, train_pred) * 100`: the accuracy as a percentage, comparing the predicted prices with the real prices. It is added to the list.

`print(f"...")`: the f before the quotes makes it an f-string, which lets me put variables inside curly brackets. `{epoch:3d}` prints the epoch as a whole number with a width of 3 characters, so the lines line up. `{train_costs[-1]:.5f}` takes the last item of the list ([-1] counts from the end) and shows it with 5 decimal places. `{train_accs[-1]:.2f}` shows 2 decimal places. The text pieces on separate lines inside the brackets are joined together into one line of text.

Problem: I need to find the 20 weights that make the predictions as close as possible to the real prices, without using a library to fit the model, and I also need a record of how the cost and the accuracy change over the epochs.

Solution: Run gradient descent for 300 epochs, starting from zero weights, and update the weights using only the train data. After every epoch, print and save the cost and the train and test accuracy. The result: in epoch 1 the cost is 3594.10697, the train accuracy is 36.33% and the test accuracy is 22.31%. The start is poor because all the weights begin at 0, so the first predictions are 0 for every row, which is far from real prices. After that the bias and the weights quickly move to the right values. By epoch 300 the cost has dropped to 58.77789, the train accuracy is 98.96% and the test accuracy is 96.79%. The numbers change fast at the beginning and then flatten out, which means the model has almost finished learning.

mae = np.abs(y_test - final_pred).mean()
rmse = np.sqrt(((y_test - final_pred) ** 2).mean())

print("Final train accuracy (R2):", round(train_accs[-1], 2), "%")

`final_pred = predict(X_test, w)`: uses the final trained weights to predict the test rows. These are already real prices, because close was never scaled.

`np.abs(y_test - final_pred)`: the real price minus the predicted price for each row, with the minus sign removed (abs means absolute value), so every error is positive. `.mean()` averages them. This is the MAE (mean absolute error): on average, the prediction is off by this many price units.

`((y_test - final_pred) ** 2).mean()`: squares the errors and averages them, which is the mean squared error. `np.sqrt(...)` takes the square root, which brings it back to price units. This is the RMSE. It is always at least as big as the MAE, and it is bigger when there are a few large mistakes, because squaring punishes big errors more.

`round(number, 2)`: rounds to 2 decimal places, so the printed numbers are short and tidy.

`train_accs[-1]` and `test_accs[-1]`: the last item in each list, which is the accuracy after the final epoch (epoch 300).

`train_final_pred = predict(X_train, w)`: uses the final weights to predict the train rows. I need these to calculate the final train accuracy.

Summary of the whole program

2. Load train.csv and test.csv.
3. Choose the 15 number columns as inputs.
4. Turn the fake zeros into empty cells and fill all the empty cells with the train median.
5. Remove the rows with no real Close price.
6. Turn the stock names into 0/1 columns (one-hot encoding).
7. Split into X (inputs) and y (Close price) as NumPy arrays.
8. Standardize the input columns X with the train mean and std (close is left as it is), and add the column of 1s for the bias.
9. Write the functions by hand: predict, cost and r2_score.
10. Train with gradient descent for 300 epochs and record the cost and accuracy after each one.
11. Plot the cost after each epoch.
12. Plot the accuracy after each epoch.

14. Print the expected and predicted prices side by side, save all the predictions to a file, and print every final number (cost, accuracy, MAE, RMSE) once in a summary.


Epoch: one full pass through all the training rows.

Weight: a number that tells the model how much an input column matters.

Bias: the weight w0 that is not tied to any column. It is learned using the column of 1s.

Cost: a number that shows how wrong the model is. Gradient descent tries to make it small.

Gradient: the direction (and slope) in which the cost goes up fastest for each weight. I move the weights the opposite way.

Learning rate: how big a step I take at each update.

One-hot encoding: turning a column of words into one 0/1 column for each word.

Standardization: rescaling a column to have a mean of 0 and a standard deviation of 1.

Data leakage: accidentally using information from the test data while training, which makes the accuracy look better than it really is. I avoid it by taking the medians, means and stds from the train data only.

R2 score: the accuracy for regression. 100% is perfect, and 0% means no better than always guessing the average.

MAE and RMSE: two ways of showing the average size of the prediction mistakes, in the same units as the price.
